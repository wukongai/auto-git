# 安全检查、结果状态与继续方式

[返回Auto Git入口](../SKILL.md) · [工作流](workflow.md) · [安全边界](safety.md)

## 这次提交究竟检查了什么

Auto Git先精确暂存批准文件，再运行真实staged integrity检查，核对空白错误和冲突标记。文档的integrity档不证明业务正确；代码和配置变更缺少显式项目回归命令时停止。每次回执列出实际命令、退出码和检查档位；没有执行的检查不能报告通过。

Commit前固定批准树与原HEAD；Commit后检查实际树、父提交、文件范围、当时的index及Git可见工作区。Hook扩大范围、改变内容或遗留额外暂存时，已发生的Commit和文件保留，结果不能标成功。后续合法暂存不改变原Commit本身的核验事实；`captured_post_commit`明确认证当时捕获的index，不声称当前index永远不变。

## 结果状态

| 状态 | 含义与继续方式 |
|---|---|
| running | 操作已开始；会话中断后先只读核验，不盲目重放 |
| succeeded | 当前动作的所需后置条件已有验证；不自动批准下一动作 |
| failed | 已确认的本地动作未完成；读回现场后重新计划 |
| partial | 部分配置或动作已发生，完整合同未满足；保留成果，只处理未完成部分 |
| verification_failed | Commit等已产生，但范围、内容或其他核验未通过；不自动reset |
| unknown | 网络或读取中断，尚不能确定是否执行；恢复读取后用原目标核验 |

推送核验同时检查批准目标、本地HEAD、远端OID和upstream。远端已收到但本地跟踪尚未匹配时，报告部分完成；不重复推送来掩盖配置缺口。两端已对应且upstream正确时，无需再次Push。

操作开始前保存必要目标；失败日志只保存稳定错误分类和安全短说明，不保存Hook输出、完整diff或任意正文。凭证形态路径只按名称报告并阻断提交，inspect只取元数据；示例文件名不能证明正文无凭证。Git忽略文件不在工作区副作用摘要范围内。

## 当前能力边界

index恢复只处理Auto Git拥有的暂存区备份，不能代替工作区单文件恢复。受管快进拉取、冲突解决、soft-uncommit、恢复ref和后台同步尚未实现；遇到这些请求应明确交接标准Git方案，不假装执行。缺少完整核验证据的旧Commit记录需要重新核对，不能仅凭HEAD相同认证全部安全条件。
